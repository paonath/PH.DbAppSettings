### AGENTS.md (repo root)

```markdown
# Portal — Agent Guide

## Solution Overview
Portal is a project management platform that exposes a MinimalAPI (.NET 9) backend and an Angular 19 SPA frontend. It manages Projects, Users, and associated resources for internal teams.

## Architecture reference
- Blueprint: `specs/portal-blueprint.md`
- Template: `.agents/templates/solution-architecture-template.md`

## Cross-cutting rules
- Schema changes → numbered SQL script in `diff/` (no EF migrations)
- Specs in `specs/`; completed specs in `specs/implemented/`
- Never: duplicate entity classes between projects; add business logic to Api layer
```

### Portal.Api/AGENTS.md

```markdown
# Portal.Api — Agent Guide

## Purpose
Minimal API entry point. Routes HTTP, registers DI, configures middleware and authentication.

## Belongs here
- `Program.cs` — DI registration, middleware pipeline, MapGroup calls
- `ServiceRegistration.cs` — scoped service + validator registration
- `GlobalUsings.cs`
- `Endpoints/Project/ProjectEndpoints.cs`
- `Endpoints/User/UserEndpoints.cs`
- `Endpoints/EndpointMap.cs`

## Does NOT belong here
- Business logic → Portal.Services.Components
- Database access → Portal.Dal
- DTO definitions → Portal.Models
- Validation rules → Portal.Services.Components

## Conventions
- Endpoint handlers: private static async methods
- Authorization: .RequireAuthorization() at group level, never omitted
- No manual validation: inject IValidator<T> from DI only
- Routes: GET/POST /api/project/, GET/PUT/DELETE /api/project/{id}; same for /api/user/

## Dependencies
Portal.Dal, Portal.Models, Portal.Services, Portal.Services.Components, PortalCommon (optional)
```

### Portal.Dal/AGENTS.md

```markdown
# Portal.Dal — Agent Guide

## Purpose
Data-access layer. Owns all EF entity classes and DbContext.

## Belongs here
- `Context.cs` with:
    - DbSet<Project>
    - DbSet<User>
- `IUnitOfWork.cs` + `UnitOfWork.cs`
- `DapperBase.cs`
- EF entity classes: `Project.cs`, `User.cs`

## Does NOT belong here
- DTOs → Portal.Models
- Business logic → Portal.Services.Components

## Conventions
- Entity classes never exposed outside this project
- New entity → add DbSet<T> to Context.cs
- Schema change → new numbered SQL script in diff/ (no EF migrations)

## Dependencies
PortalCommon (optional)
```

```markdown
# Portal.Models — Agent Guide

## Purpose
DTO layer. C# record types for API input/output only. No EF entity classes.

## Belongs here
Read DTOs:   ProjectDto, UserDto
Write DTOs:  ProjectCreateDto, UserCreateDto

Folder layout:
  Project/ProjectDto.cs
  Project/ProjectCreateDto.cs
  User/UserDto.cs
  User/UserCreateDto.cs

## Does NOT belong here
- EF entity classes → Portal.Dal
- Business logic → Portal.Services.Components

## Conventions
- All records use init properties
- ProjectDto adds only Id on top of ProjectCreateDto; same for UserDto
- No mapping logic inside records

## Dependencies
PortalCommon (optional)
```

### Portal.Services/AGENTS.md

```markdown
# Portal.Services — Agent Guide

## Purpose
Contract layer. C# interfaces ONLY — zero implementation code.

## Belongs here
- IProjectService — GetAllAsync, GetByIdAsync, CreateAsync, UpdateAsync, DeleteAsync
- IUserService    — GetAllAsync, GetByIdAsync, CreateAsync, UpdateAsync, DeleteAsync

## Does NOT belong here
- Implementations → Portal.Services.Components
- Any concrete class

## Conventions
- Every method is async (Task / Task<T>)
- Methods operate only on Dto types, never on EF entity classes

## Dependencies
Portal.Models, PortalCommon (optional)
```

---

### Portal.Services.Components/AGENTS.md

```markdown
# Portal.Services.Components — Agent Guide

## Purpose
Implementation layer. Service implementations + FluentValidation validators.

## Belongs here
Implementations: ProjectService (implements IProjectService), UserService (implements IUserService)
Validators:      ProjectValidator (for ProjectCreateDto), UserValidator (for UserCreateDto)

## Does NOT belong here
- Interfaces → Portal.Services
- Endpoint routing → Portal.Api

## Conventions
- ProjectService and UserService take IUnitOfWork + ILogger<T> via constructor
- Never bypass IUnitOfWork for DB access
- New service + validator must be registered in Portal.Api/ServiceRegistration.cs
- No ad-hoc validation: use ProjectValidator / UserValidator only

## Dependencies
Portal.Models, Portal.Services, Portal.Dal, PortalCommon (optional)
```
